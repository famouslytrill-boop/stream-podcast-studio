# Hardware to first finished episode

Use the owner’s current microphone/interface/Xbox models, not guessed hardware. The November 17 visual guide accompanies this release; account and physical device acceptance remain separate from synthetic test evidence.

1. Open the laptop’s Desktop → EmberBanter Studio → Creator Hub shortcut. Version 0.7.0 is the target. Keep the private workspace outside Git and the laptop awake for renders.
2. Connect one microphone path: XLR mic → interface → USB laptop, or USB mic → laptop. Follow the manufacturer’s driver and phantom-power instructions. Use headphones. Select the exact input in Windows and OBS. Avoid capturing the same device globally and as a scene source.
3. Choose an Xbox path: supported browser Remote Play with the owner’s account/network, or a compatible HDMI capture card. Test game audio and permitted party chat separately. Do not buy a card before checking the existing network path and actual hardware constraints.
4. Run OBS Auto-Configuration Wizard, then build Starting / Gameplay / Talk / BRB / Ending scenes. Existing brand masters supply artwork; they do not route audio or import a complete hardware configuration. Start with a conservative local 720p30 SDR rehearsal. Screen Hz, game FPS, output FPS and HDR are different.
5. Keep a full audio mix on recording Track 1 and, if useful, isolated mic/game tracks separately. The hub episode editor chooses one track per segment; it does not silently recombine every track. Keep recording format and codecs compatible with the intended editing path.
6. Record a private local rehearsal: normal/loud speech, gameplay, a clear sync cue, BRB and return. Stop and let the file finish. Watch/listen with headphones and inspect representative OBS Stats. Do not treat a short synthetic encoder check as sustained acceptance.
7. In Capture inbox, scan only the configured folder and select the intended finished capture. Confirm it is stopped, review the exact proposal and approve the protected import. Prepare a compatible MP4 editing copy when useful; keep the original.
8. In Episodes, arrange reviewed source segments, chapter labels and the intended audio track. Correct captions using final arranged timing. Studio’s single-source captions use original-source timing. Review the exact export, inspect decode/receipt evidence and perform full editorial listening/picture review.
9. In Create, generate optional narration using an installed voice or save a storyboard. One to eight scenes, max four minutes; 0 seconds uses measured local narration. Short footage needs explicit loop approval. Footage audio is replaced by speech/silence. Local TTS is synthetic, not an identity clone or a promise of all languages.
10. In Platforms, prepare title/topic/description/source-linked metadata, script and message drafts. An optional timezone-aware ICS is a reminder import. Nothing is sent, uploaded, automatically scheduled or publicly broadcast. Open an official platform portal and sign in personally; verify account eligibility, visibility, audience, rights and disclosures before publication.
11. For a phone, establish a private HTTPS reverse proxy and owner device connection. Tailscale Serve is one researched option; its authenticated setup is not complete. After jobs finish, start the hub with --public-origin set to the actual HTTPS hostname. Pair the phone with the private laptop key; never expose it in chat. Do not use public Funnel or expose OBS ports. Phone web control and a hosted ChatGPT tool bridge are different connections.
12. In History, inspect failures and correct causes. Review replay prepares a new expiring action for eligible file jobs only. It never repeats OBS actions, launches or capture imports, and it rejects changed plan/capability assumptions. Repair a specific failure; do not grant arbitrary code or OS write access.
